FastSID -- the K4510's cheap SID engine
=======================================

Upstream
  VICE, the Versatile Commodore Emulator -- https://vice-emu.sourceforge.io/
  Taken from BMC64's vendored copy, which is what the Pi side of this
  project already builds against:
      https://github.com/randyrossi/bmc64
      third_party/vice-3.3/src/sid/fastsid.c
                              src/sid/fastsid.h
                              src/sid/wave6581.h
                              src/sid/wave8580.h
                              src/fixpoint.h
  i.e. VICE 3.3 with BMC64's changes.  Its RASPI_COMPILE blocks (a second
  SID model resource, a chip number in open()) are present in the source
  but NOT compiled here: the K4510 has four chips, not two, and picks the
  model per chip through its own resources_get_int (core/fsid.c).

  Local clone this was copied from, 2026-08-30:
      ~/Repositories/VICE_Projects/bmc64

Altered
  No.  These five files are byte-for-byte upstream:
      fastsid.c  fastsid.h  fixpoint.h  wave6581.h  wave8580.h

  Every OTHER header in this directory is a K4510 shim, written here, that
  stands in for the emulator fastsid.c expects around it:
      vice.h lib.h log.h machine.h maincpu.h resources.h
      sid.h sid-snapshot.h snapshot.h sound.h types.h
  They supply an allocator, a CPU clock, two settings and the engine-hook
  struct -- nothing else was needed.  sid-snapshot.h carries two structure
  definitions copied from VICE's own, because fastsid.c compiles its
  state_read/state_write against them; the K4510 saves state its own way
  (core/state.c) and never calls them.

  The wrapper that drives all this is core/fsid.c, which is ours.
